# 面试讲解提纲

定位：具备故障治理的多 Agent 电商推荐个人工程项目，不宣称生产规模。

建议演示五分钟：业务目标与约束 → 推荐及点击闭环 → Agent 执行状态 → 文案后台缓存 → 故障测试与当前边界。

需要能解释：
- 为什么使用固定 LangGraph 工作流，而非自由规划？如何确定节点依赖？
- 库存为何使用确定性数据库工具？模型能否改价格？
- 重试、超时、并发限制、准入和熔断分别解决什么问题？
- 为什么将文案移出同步链路？任务丢失会产生什么影响？
- 幂等键为何必须验证内容一致？Redis 不可用会不会丢行为？
- 应用取消为什么不能终止 SQL？statement timeout 的范围是什么？
- 测试覆盖与实际生产可靠性有什么区别？规则画像是否已经足够？

可写简历：编排四类业务角色、实现行为幂等与持久化、模型降级和熔断、后台文案缓存、故障测试与合成规则评测。不要写未知 QPS、CTR 提升、百万用户或企业级上线。
